### 1. Outcome and boundaries

An operator can ask an admitted lane to continue its work in another harness. The target recovers the intended conversational context, workspace, profile and stable communication identity. Exactly one current execution may receive actionable input or act for the role. The predecessor can exit gracefully after the successor is independently verified. A separately authorized recovery orchestrator can perform this for a specifically named lane, including a crashed predecessor. File access, matching cwd, possession of a transcript, and knowledge of an identity name each confer zero transfer authority.

A local native resume uses the same machine, compatible harness, managed home and admitted profile pin. Changing harness builds a fresh target conversation; its UUID can differ. The converter produces a private projection, loss report and publication receipt. An operator can explicitly request only history. That request carries no promise of identity continuity or authority to terminate the source. Cross-machine export, provider credential transfer and production Namecoin registration are later work.

**Baseline sources:** [Swarma session launch and host](https://github.com/relux-works/swarma-docs/blob/bc1132c/book/ru/07-zapusk-i-host-sessiy.md), [Curator](https://github.com/relux-works/swarma-docs/blob/bc1132c/book/ru/08-curator.md), [Keeper obligations](https://github.com/relux-works/swarma-docs/blob/bc1132c/book/ru/15-keeper.md), [the orchestrator cycle](https://github.com/relux-works/swarma-docs/blob/bc1132c/book/ru/20-orkestrator-i-cikl.md) and [bridge delivery](https://github.com/relux-works/swarma-docs/blob/bc1132c/book/ru/24-soobscheniya-i-most.md). The platform chapter owns the architectural rules. Protocol refinements belong in the affected module specs and vectors. A proposed change to authority or custody requires the responsible guardian’s decision.

### 4. Identity, authority and records

A **profile** can be reused by multiple agents. A **stable identity** survives a session, model or harness change. A **binding** routes that identity to one current execution. The project keeper profile `session-convert_product_keeper` and Matrix identity `ivmbp_agent-session-convert_orch` illustrate the distinction. A Matrix account exists; Namecoin registration for it has not been established.

For a new lane, resolve an explicit assignment or a policy-authorized automatic assignment. Key the resolver by authorized operator/product scope and stable assignment ID. Reuse the existing record on a retry. On resume, resolve identity from the admitted conversation/launch record. The caller can propose a role; current directory, ambient `A2A_AGENT`, hook contents and remote messages cannot independently authorize it. A distinct requested recipient is an explicit role-transfer operation with its own grant.

Proposed private operation journal fields: schema/revision, operation ID, intent digest, initiating principal and grant reference, source provider/session/physical workspace/profile/home reference/lock, source execution and lease generation, canonical target tuple, source fingerprint, identity assignment and transport reference, intended recipient, actual target UUID, matching host registration and controller epoch, phase, evidence refs, failure reason and recovery coordinator. Persist secrets nowhere in the journal. Keep trace references local, retention bounded and machine-readable output free of message content. Separate timestamps and receipt IDs for publication, process start, effective hooks, association, witnessed wake and source retirement.

### 5. Transfer transaction

1. **Admit.** Validate requester scope for this source. Resolve the unique source UUID through registered managed stores. Resolve the target under the same approved profile and lock. Validate host capability, effective permissions, login availability, target writer support and declared communication requirement. For notified moves compare source role and intended recipient with the selected identity and target hook configuration before fork. Capture the original mailbox route and subscription facts. An unsupported target can offer an explicitly selected context-only export.
2. **Reserve.** Persist intent and a compare-and-swap execution fence. A repeat of the same operation can resume it; a different intent for the occupied source refuses. Preflight the source snapshot and verify the log has not advanced past the cutover boundary.
3. **Prepare history.** Capture once; stage projection and inspect it. Publish through the qualified provider path and persist the target-issued ID. If the response was lost, reconcile the provider receipt and store before allocating another target. A verified publication can survive a subsequent hook or host failure.
4. **Quiesce the predecessor.** Ask its current execution holder to drain or park actionable work. Fence old mailbox delivery and outbound role effects. Keep an observable predecessor and preserve pending mail. Obtain explicit acknowledgement of release of the exclusive binding. A live predecessor with no such handshake blocks automatic movement today.
5. **Start the successor.** Launcher dispatches the published resume through the selected host exactly once. The Host revalidates profile, digest, member, workspace and permit. Record target process-start acknowledgement. On uncertain observation, return a pending outcome and reuse the operation ID.
6. **Verify communications.** Plugin uses the actual target thread, execution, epoch and current lease. For Codex, query effective hooks in the target home/workspace and check enabled state, command, identity and trust. For other providers use admitted runtime-specific evidence. Operator-only trust remains pending. Verify subscription coverage, including authorized human principals. Independently observe a new event addressed to the original recipient, automatic wake from idle, inbox read and reply correlated to that event and identity.
7. **Commit and retire.** Atomically publish the new binding as authoritative. After successor evidence and explicit retirement admission, gracefully retire only the captured predecessor execution under its current generation. Preserve source history. Record the actual exit and release. A lost stop acknowledgement leaves retirement pending; repeated recovery cannot kill a recycled PID, new pane or an unrelated worker.
8. **Recover.** Before binding transfer, preserve the predecessor or resume it through its existing authority. After transfer, keep the new authoritative generation until a separately authorized compensating operation. Never restart both consumers. Operator pause, unknown generation, stale permit, changed lock, lost transport or changed source history park the transaction and preserve evidence.

Tests must interrupt after each durable boundary. Include simultaneous requests, a trust prompt, expired lease, target exit before ready, unrelated active role, changed config between parent and child, and crash during retirement. Observe actual session counts, identities, files and ledger transitions after retry.

### 6. Same-directory incident and socket incident

**Identity regression fixture.** Give source Muse the synthetic role A, target Codex in the same workspace historical hooks for B, and the parent shell C. Require exactly one current consumer, the old generation fenced, and reply by A on the expected target thread. A healthy neighbor is the mandatory negative control. HTTP model errors are classified independently.

**Socket observations.** The registration identifies an absolute backend executable and server/endpoint. A named terminal is scoped to that server. Model outcomes as present, authoritatively absent, and unknown/unavailable. Only confirmed absence on the intended authorized endpoint admits creation. EPERM, EACCES, timeout, unreachable wrong server, malformed response and an unconfirmed lease holder must result in no create, no hook write and no lease acquisition. Require a trusted host-side observer when the sandbox cannot inspect it. Test attach to an existing pane and fresh creation as adjacent positive cases. Keep runtime sandbox policy independent of observation authority.
